Scope: one Draft PR to main. No Production/Staging execution or live secret read.

## Delivered and source-verified changes

1. Canonical scoped device inventory, elimination of historical hostname defaults, tenant/user isolation and revoked/archived denials.
2. Distinct diagnostic/installer/execution intent. A Stale device may be diagnosed but not receive command execution.
3. No shared-control-plane health target or cross-device global credential fallback.
4. Signed installer capability fenced to current credential epoch at issuance, claim, and final redemption; direct raw Admin BAT download disabled (HTTP 410).
5. Secure headers for protected installer links and material, no cross-origin health redirects; token in a URL remains a residual security concern and requires access-log redaction validation.
6. Heartbeat/policy require device-owned credential; unique lifecycle-bound config, tri-state route health, idempotent DB update readback, and disabled route cannot be revived by on-duplicate heartbeat.
7. Watchdog rebuilt from clean code: per-device Cloudflare route, canonical IDs, secret file, verification after restart or rollback. Real PowerShell/Windows acceptance pending.
8. Operational health proof differs from hardware proof. RECOVERED remains false until independent nonexportable device-generation attestation is supported.
9. Hostinger recovery registry has seven planned command keys and a non-mutating discovery endpoint; registered target command allowlist is not silently expanded.
10. Existing productionRecoveryControlStoreBootstrap/recoveryControlDb/productionRecoveryAuthorityPreflight retain Recovery authority: new Hostinger metadata is not a parallel kernel.
11. Official Hostinger API has account database create and NodeJS environment operations, but connection-specific permissions were not confirmed.
12. Hostinger NodeJS PUT environment API is full-replace-and-restart with masked GET readback. A safe partial update is unsupported without a complete trusted source and a certified conditional/revision guard. New provider contract refuses actual execution.
13. Canonical OpenAPI and Admin Core projections updated for legacy BAT retirement; generated byte parity remains to be certified.
14. Adversarial specs added to Feature 009 and Hostinger Spec 014.

## Highest risk residual blockers

P0 — Nonexportable physical device-generation challenge/response attestation does not yet exist. Exportable .env identity cannot prove original hardware; true RECOVERED is intentionally blocked.

P0 — Production Recovery Control Store existence, host account entitlement, missing DB role and provider writer are unverified. Current Hostinger SSH connectivity is not CREATE DATABASE or Node environment write authorization.

P0 — Hostinger full environment replace may delete unknown secrets and restarts the live Node app. No mutation executor should be enabled until complete authoritative env values, external lock and provider revision assurance are available.

P0 — Durable cross-process recovery idempotency/lease, failure budget and stateful rollback receipt remain incomplete; Watchdog isolated smoke and run-loop storm tests are needed.

P1 — Real new/old Local Connector compatibility migration. Legacy backend credential heartbeat will no longer work, old agents may lack canonical IDs and scoped secret file.

P1 — Signed installer capability uses URL query parameter. Even with no-store/referrer protections, reverse proxy and application access logs must redact tokens; full POST-only secret-free link transport is future hardening.

P1 — Native CI and generated OpenAPI byte-for-byte parity are unverified. Existing CI queue is not success or failure proof.

P1 — PowerShell script AST/Windows tests and DB schema collation/nullable identity fixtures were not run against actual native environments.

P1 — Cross-provider account and website id, entitlement lease, secret intake, role ownership, actual DB CREATE and same-cycle readback require a separate approved adapter. There is no free-form SSH fallback.
