## Incident

- Impact: `auth.mad4b.com` and `dev.mad4b.com` returned `503 Service Unavailable`.
- Root cause: `http-generic-api/routes/agentGovernanceRoutes.js` evaluated request-scoped variables at module import time. The undefined references crashed server startup on every rebuild from `main`.
- Recovery commit: `aecf4c95`.
- Mainline recovery confirmation: `db7c775a` includes the recovery.

- Restored request-scoped declarations to the governed route handler.
- Expanded `test-hostinger-startup-imports.mjs` to import `routes/index.js`, covering top-level route import failures before deployment.
- Ran the Node 22 test manifest successfully: 446/446 tests passed.
- Verified live recovery:
  - `GET https://auth.mad4b.com/health` returned `200`.
  - `GET https://dev.mad4b.com/health` returned `200`.
  - The affected agent-governance route returned an authorization response instead of `503`.

## Remaining Provenance Gap

The recovered runtime did not expose a deployment manifest. `/version` therefore reported `deployment_validation_incomplete`, and the development hostname inferred branch `dev` from hostname fallback while serving commit `db7c775a`.

Required deployment controls:

1. Generate `deployment-manifest.json` during the deploy/rebuild lifecycle.
2. Set the intended deployment branch explicitly through the deployment environment.
3. Treat hostname-derived branch labels as fallback evidence, not authoritative provenance.
4. Validate `/health`, `/version`, and `/deployment-info` after every rebuild.
