# نظرة عامة عربية

الهدف هو تحويل طلب المستخدم الطبيعي إلى عملية مؤكدة ومحددة المورد بدل بناء الخيارات من التخمين أو اسم التطبيق فقط.

```text
المستخدم → النية → Tenant/Workspace/Brand → النشاط → المورد → Provider/Connection → Capability/Action → Schema → الجاهزية والصلاحية → Questionnaire → Preview → Execution → Readback
```

القواعد الحاكمة:

1. خيار الاستبيان يفهم النية ولا يثبت وجود قدرة تنفيذية.
2. التطابق المطلوب قبل التنفيذ هو Tenant + Workspace + Brand + Resource + Grant + Connection.
3. الجاهزية متعددة الأبعاد وليست `ready=true` فقط.
4. البيانات الحية تتفوق على الفهرس الداخلي قبل التنفيذ.
5. الأسئلة تأتي من schema الحقيقية وتسأل الحقول الناقصة فقط.
6. الصلاحيات لا تتوسع من Brand إلى Workspace دون موافقة واضحة.
7. كل توصية تمر على فحص تناقضات مع الحالة الحية.
8. كل mutation تحتاج Preview وApproval وIdempotency وReadback.
9. الاستجابة لا تعرض أسرارًا أو معرفات داخلية أو بيانات Tenant آخر.
10. التنفيذ يشمل WordPress والإعلانات وCRM والتحليلات والـworkflows والأجهزة وكل قدرة مستقبلية.

هذه الحزمة Specification فقط ولا تنفذ دعوة أو نشرًا أو تعديل جهاز أو migration أو deployment.
