# Requirements Checklist

- [x] Problem/source incident are explicit.
- [x] Scope/non-goals prevent competing authority and direct provider writes.
- [x] Intent is separated from capability authority.
- [x] Full context inheritance is defined.
- [x] Exact resource/Connection binding is mandatory.
- [x] Multi-dimensional readiness/freshness is defined.
- [x] Tool callability requires descriptor/export/route/authority/readiness/certification/readback parity.
- [x] Questionnaire options carry evidence classes.
- [x] Contradiction detection covers devices, grants, publishing, stale evidence, and duplicates.
- [x] Preview, approval, idempotency, execution, readback, unknown outcome, and retry are defined.
- [x] WordPress, ads, CRM, analytics, workflows, devices, connections, support, and future capabilities are covered.
- [x] Arabic/localization behavior is defined.
- [x] OpenAPI 3.1 and structured errors are included.
- [x] Success criteria are measurable.
- [ ] Product, platform, security, and Tenant UX owners approve.
- [ ] Implementation PR sequence receives named owners.
