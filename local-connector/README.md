# local-connector

A lightweight break-glass HTTP connector running on a Windows device and exposed through the shared Admin Recovery transport. It serves two purposes:

1. **Break-glass recovery** — the Admin Recovery surface can call the device connector through the governed recovery channel.
2. **Platform-orchestrated device ops** — the platform API (`/dispatch`, `/local-connector/*`) resolves tenant → user → device → config → route and calls the selected connector runtime.

The local Node server binds only to `127.0.0.1`; Cloudflare Tunnel is the external transport. Environment authority does **not** come from `connector.mad4b.com`: the connector runtime is bound to its environment/control plane through `.env` and the policy/heartbeat URLs generated by the canonical connector-agent installer.

`connector.mad4b.com` is the shared Admin Recovery transport. The Connector-owned Windows tunnel runtime is:

```text
Mad4B-LocalConnector-Cloudflared
```

Do not treat a generic Windows service named `cloudflared` as Connector-owned. Do not reuse, stop, uninstall, rename, or reconfigure `Mad4B-Staging-Cloudflared` from Local Connector installation or recovery flows.

## Setup

### Option A — Local Manager / GPT-assisted (recommended)

1. Request a short-lived installer link through the Local Manager/Admin connector install flow.
2. `format=ps1` resolves directly to `/connector-agent/installer.ps1`.
3. `format=bat` returns a small bootstrap only; the BAT downloads and executes that same canonical PowerShell installer.
4. Run the resulting installer as Administrator.
5. The canonical installer verifies the connector-agent manifest and SHA256 values, writes the environment-bound `.env`, installs/updates the Connector-owned Node service and `Mad4B-LocalConnector-Cloudflared`, then requires local health before success.

The canonical installer is the only supported installer implementation. Legacy download routes delegate to it and must not contain an independently executable Cloudflare service installer.

### Option B — Manual operator invocation

Manual installation still uses the canonical installer. Obtain a current short-lived `ps1` download link from the platform and run the downloaded script as Administrator. Do **not** replace this with:

```powershell
cloudflared service install <token>
```

and do not install the Connector tunnel into a generic `cloudflared` Windows service.

The canonical runtime uses a restricted token file and dedicated ownership:

```text
CONNECTOR_CLOUDFLARED_SERVICE=Mad4B-LocalConnector-Cloudflared
CONNECTOR_CLOUDFLARED_TASK=Mad4B-LocalConnector-Cloudflared
CONNECTOR_CLOUDFLARED_MANAGEMENT=remote
CONNECTOR_CLOUDFLARED_TOKEN_FILE=<restricted local token file>
CONNECTOR_CLOUDFLARED_METRICS=127.0.0.1:49313
```

The token file ACL is restricted to the installing identity/System as appropriate to the installer contract. Tokens must not be placed inline in service command lines, logs, metrics, heartbeat payloads, or runtime-state evidence.

### Environment binding

The generated connector `.env` must include a consistent environment/control-plane set:

```text
CONNECTOR_ENVIRONMENT=production|staging
CONNECTOR_CONTROL_PLANE_BASE_URL=https://auth.mad4b.com|https://dev.mad4b.com
CONNECTOR_POLICY_URL=<same control plane>/connector-agent/policy
CONNECTOR_HEARTBEAT_URL=<same control plane>/connector-agent/heartbeat
```

Supported host binding is fail-closed:

- `production` → `auth.mad4b.com`
- `staging` → `dev.mad4b.com`

A Staging connector with a missing or Production policy URL must not silently fall back to Production. The historical Production policy fallback is compatibility-only and requires an explicit Production-only compatibility flag.

### Diagnosing tunnel errors

Cloudflare error **1033** may be transient. Retry connector health with bounded backoff before repairing the tunnel. When tunnel runtime inspection is required, inspect the Connector-owned runtime only:

```powershell
Get-Service Mad4B-LocalConnector-Cloudflared
Get-Service local-connector

# Connector-owned logs are under the Local Connector runtime root.
Get-Content .\cloudflared.log -Tail 100
Get-Content .\cloudflared-error.log -Tail 100
Get-Content .\connector.log -Tail 100
Get-Content .\connector-error.log -Tail 100
```

The dedicated cloudflared metrics listener is loopback-only (`127.0.0.1:49313`). Do not use `Get-Service cloudflared` / `Start-Service cloudflared` as the Connector repair procedure because a generic service may belong to another installation.

Before and after installer/recovery actions, preserve non-interference with:

```text
cloudflared
Mad4B-Staging-Cloudflared
```

The Connector installer/watchdog owns only:

```text
Mad4B-LocalConnector-Cloudflared
local-connector
Mad4B-LocalConnector-Watchdog
```

## Endpoints

| Method | Path       | Auth required | Description                                        |
|--------|-----------|---------------|----------------------------------------------------|
| GET    | `/`        | No            | Health check — hostname, platform, uptime          |
| GET    | `/health`  | No            | Same as `/`                                        |
| POST   | `/github`  | Yes           | Run governed/allowlisted local GitHub CLI operations where enabled |
| POST   | `/gcloud`  | Yes           | Run governed/allowlisted local gcloud operations where enabled     |
| POST   | `/shell`   | Yes           | Run an allowlisted command alias (see below)       |
| POST   | `/files`   | Yes           | Read or write an allowlisted file path             |

All error responses use the shape `{ ok: false, error: { code, message } }`.

Authentication: send `Authorization: Bearer <CONNECTOR_SECRET>` or `x-connector-secret: <CONNECTOR_SECRET>` on authenticated connector requests. `CONNECTOR_SECRET` is an Admin break-glass/device credential. Existing admin devices may continue using `CONNECTOR_LOCAL_API_KEY` only as the documented compatibility alias. `BACKEND_API_KEY` is not a standalone Connector credential except during an explicitly governed legacy-device migration window.

## Shell allowlist format

`CONNECTOR_SHELL_ALLOWLIST` is a JSON object in the `.env` file. Each key is the alias name callers pass in the request body.

```json
{
  "git_status": {
    "command": "git",
    "args": ["status"],
    "display_name": "Git status",
    "allow_extra_args": true,
    "max_extra_args": 2,
    "timeout_ms": 30000
  },
  "node_ver": {
    "command": "node",
    "args": ["--version"],
    "display_name": "Node version"
  }
}
```

Fields:

| Field | Required | Default | Description |
|---|---|---|---|
| `command` | Yes | — | Executable name or absolute path |
| `args` | Yes | — | Fixed argument array |
| `display_name` | No | alias | Human-readable label |
| `allow_extra_args` | No | false | Whether bounded caller args may be appended |
| `max_extra_args` | No | 10 | Maximum caller-supplied args |
| `timeout_ms` | No | 120000 | Per-alias timeout override (max 600000) |

Shell request body for `action=run`:

```json
{ "action": "run", "alias": "git_status", "extra_args": ["--short"], "timeout_ms": 15000 }
```

### Required local verification aliases

Every connector used for platform administration should expose the governed verification aliases required by its policy, such as bounded disk, directory, and marker inspection. They must not be converted into arbitrary filesystem traversal or arbitrary shell execution.

## File endpoint

Enable with `CONNECTOR_FILES_ENABLED=true` and list allowed absolute paths in `CONNECTOR_FILE_PATHS`.

```text
CONNECTOR_FILES_ENABLED=true
CONNECTOR_FILE_PATHS=C:\path\to\file.txt,C:\another\config.json
```

Actions include bounded `list`, `list_drives`, `locate_repo`, `read`, and `write` against allowlisted paths. Path resolution occurs before access is granted.

---

## Dependency installer endpoint

Enable with `CONNECTOR_DEPENDENCIES_ENABLED=true`. Only package keys in `CONNECTOR_DEPENDENCY_ALLOWLIST` may be installed. Keep this allowlist narrow; this endpoint is not a generic package-management shell.

---

## Apps and browser endpoints

Enable with `CONNECTOR_APPS_ENABLED=true`. App/browser control uses `CONNECTOR_APP_ALLOWLIST`; callers select allowlisted aliases rather than supplying raw commands.

`POST /apps` supports bounded app lifecycle actions. `POST /browser` supports allowlisted browser actions such as opening an absolute HTTP(S) URL and screenshot capture. Consequential web actions remain governed separately.

---

## Transport model

No public IP or inbound firewall opening is required on the Windows device. `Mad4B-LocalConnector-Cloudflared` establishes an outbound tunnel and forwards Connector traffic to `127.0.0.1:7070`.

The public hostname is transport, not tenant/environment authority. The Auth runtime resolves the target identity and environment before selecting the Connector route. Admin Recovery can fall back to the shared `connector.mad4b.com` transport only through explicit Admin Recovery intent; tenant routing must not silently fall back to it.

The Cloudflare tunnel configuration is remotely managed. The local service uses a restricted token file, dedicated loopback metrics, and Connector-owned logs. The canonical installer must not mutate DNS/provider configuration merely to reconcile a local Windows service.

---

## Platform-orchestrated provisioning

For new users/devices, `POST /local-connector/install` provisions the routing/configuration chain and stores the resulting device configuration in `local_connector_user_configs`. The subsequent installer download is deliberately separate:

1. provision/resolve the device configuration;
2. request a short-lived signed installer link;
3. `ps1` → canonical `/connector-agent/installer.ps1`;
4. `bat` → bootstrap that downloads the canonical PS1;
5. canonical installer verifies the manifest and installs the dedicated runtime;
6. watchdog/heartbeat certify the environment-bound runtime.

The platform keeps tenant/user/device/config/route identity separate from the shared recovery hostname.

---

## Running on another device

Do not manually copy a generic cloudflared service definition or reuse another environment's Windows service. Provision/link the additional device through the platform and use its canonical installer so its device identity, token file, environment binding, policy URL, heartbeat URL, service ownership, and evidence remain explicit.

---

## Security notes

- The Node server binds to `127.0.0.1` only.
- The Connector-owned tunnel runtime is `Mad4B-LocalConnector-Cloudflared`; the watchdog rejects a different configured ownership name.
- Tunnel credentials are stored in a restricted token file rather than an inline `cloudflared service install <token>` command.
- Cloudflared metrics are loopback-only.
- Installer/recovery flows must not mutate generic `cloudflared` or `Mad4B-Staging-Cloudflared`.
- Environment ↔ policy-host mismatch fails closed; Staging must not fall back to Production policy.
- Shell commands use allowlisted execution with `shell: false`; unsafe metacharacters are rejected.
- File access is restricted to configured allowlisted roots.
- Authenticated requests are audited without logging secrets.
